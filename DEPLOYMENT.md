# Deployment Information

## Platform

and the private `k5-day14-redis` Key Value service. 
Region: Oregon (verified in the Render dashboard; both services are in Oregon).

## Verification

CP6 public HTTP checks passed:

| Check | Expected | Result |
|---|---:|---:|
| `GET /health` | 200 | 200 |
| `GET /ready` | 200 | 200 |
| `POST /ask` without API key | 401 | 401 |
| `POST /ask` with API key | 200 | 200 |

The API key is generated by Render. It is intentionally not recorded in this
file. `REDIS_URL` is connected to the Render Key Value service by the Blueprint.

## Test Commands

Set `BASE` to the public Render URL and enter the generated key without echoing
it to the terminal:

```bash
export BASE="https://k5-day14-agent-177d.onrender.com"
read -rsp "AGENT_API_KEY: " AGENT_API_KEY; echo

curl -sS -o /dev/null -w '%{http_code}\n' "$BASE/health"
curl -sS -o /dev/null -w '%{http_code}\n' "$BASE/ready"
curl -sS -o /dev/null -w '%{http_code}\n' -X POST "$BASE/ask" \
  -H 'Content-Type: application/json' -d '{"question":"Hello"}'
curl -sS -o /dev/null -w '%{http_code}\n' -X POST "$BASE/ask" \
  -H 'Content-Type: application/json' -H "X-API-Key: $AGENT_API_KEY" \
  -d '{"question":"Hello"}'
```

Expected output: `200`, `200`, `401`, `200`.
